# KLA SEMICON India Hackathon 2026 — AI-Based Restoration of Degraded Images

Joint denoising and 2x super-resolution of degraded semiconductor inspection
images. A single feed-forward network maps a noisy low-resolution input to a
clean image at ground-truth resolution.

---

## Quick start

```bash
pip install -r requirements.txt
```

**Inference** (the entry point used for benchmarking — no source edits needed):

```bash
python inference.py --input_dir /path/to/degraded --output_dir /path/to/restored
```

**Training** (reproduces the submitted checkpoint):

```bash
python train.py --config configs/base.yaml
```

**Evaluation** on the frozen validation split:

```bash
python evaluate.py --weights weights/best.pt
```

---

## Input / output contract

| | |
|---|---|
| Input | Directory of `.npy` (float32) and/or `.png`/`.tif` images, any mix of resolutions |
| Output | One file per input, **same basename, same extension**, in `--output_dir` |
| Scale | Always 2x: 128x128 -> 256x256, 256x256 -> 512x512 |
| Input range | **Never clipped.** NoisyLR legitimately falls outside [0,1] (observed [-0.28, 2.16]) |
| Output range | **Always clamped to [0,1]**, since KLA scores images exactly as saved |
| Channels | Grayscale. An RGB-encoded grayscale PNG is collapsed to one channel |

The model is fully convolutional with no fixed-size assumption, so the same
weights handle both released resolution pairs.

## The degradation model

The problem statement names three mechanisms (speckle noise, additive Gaussian
noise, downsampling) but does not disclose their parameters or their order. We
recovered them from the provided pairs by fitting
`LR - downsample(GT)` across all 3200 samples:

| Property | Finding |
|---|---|
| Downsampling kernel | **2x2 area (box) average** — lowest residual of every kernel tested (0.0910 vs 0.0924 bicubic, 0.0940 bilinear, 0.1006 nearest) |
| Noise placement | **After** downsampling — the residual is spatially white (lag-1 autocorrelation -0.05). Noise applied at high resolution and then box-averaged would be visibly correlated |
| Speckle | **Multiplicative Gamma.** Variance fits `var(r) = d^2/L + sigma^2`; measured skew of `r/d` is **+0.357** against Gamma's predicted `2/sqrt(36) = +0.333`. Multiplicative *Gaussian* speckle would be symmetric |
| Speckle strength | L: p5=22, **median 36**, p95=57 |
| Gaussian strength | sigma: **21.3%** of images below 0.005, **median 0.021**, p95=0.073, p99=0.130 |

KLA's own slides quote `L=16.86, sigma=0.008594` and `L=18.13, sigma=0.001065`,
consistent with this fit.

Every number above is regenerated by:

```bash
python analyze_degradation.py          # writes results/degradation_analysis.md
```

`src/degrade.py` reimplements this forward model and uses it to synthesise
extra training pairs from the clean GT images. Rather than assume a parametric
family for `(L, sigma)`, it samples from **empirical quantile tables fitted on
all 3200 real pairs**, then applies a random widening factor so the tails extend
past what was observed. A first attempt that guessed log-uniform L and uniform
sigma produced pairs ~50% noisier than the real ones (residual std 0.137 vs
0.091) and would have biased the model toward over-smoothing.

Validation of the engine against the real data:

| | range | residual std | skew of r/d | per-image residual std (p10 / median / p90) |
|---|---|---|---|---|
| Real pairs | [-0.13, 1.90] | 0.0852 | +0.367 | 0.045 / 0.079 / 0.114 |
| Synthetic (exact) | [-0.72, 2.00] | 0.0945 | +0.299 | 0.050 / 0.081 / 0.135 |
| Synthetic (widened) | [-1.01, 2.47] | 0.1010 | +0.483 | 0.045 / 0.086 / 0.145 |

Training batches are **50% real pairs / 50% synthetic**: the real pairs anchor
the exact test distribution, the synthetic ones widen it. The engine also
randomises the resampling kernel and the order of the three degradations, since
the brief states the order is not disclosed.

## Architecture

NAFNet-style body running at **LR resolution**, with a single PixelShuffle x2
upsample at the end.

```
input (B,1,H,W)
  -> conv3x3, width 64
  -> 16 x NAFBlock  (depthwise conv + SimpleGate + simplified channel attention)
  -> conv3x3 (long residual)
  -> conv3x3 -> PixelShuffle(2)
  -> conv3x3 -> 1 channel
  + bilinear(input, x2)          # global residual
output (B,1,2H,2W)
```

0.68 M parameters.

**Why this shape:**

- Keeping the body at LR resolution is ~4x cheaper than a U-Net operating at
  output resolution. End-to-end throughput is a scored axis.
- NAF blocks reach near-transformer restoration quality with pure convolution.
  Attention backbones (SwinIR, Restormer) gain little at 128x128 tile sizes and
  cost substantial H100 throughput.
- **No BatchNorm anywhere** — all normalisation is channel-wise LayerNorm, so
  results are batch-size independent. Verified: `max|batch8 - batch1| = 4.8e-07`.
- Per-block residual scales initialise at zero, so a 16-block stack starts as an
  identity map and trains stably at lr=1e-3 from scratch.
- The global bilinear skip carries some input noise through, which the final
  conv must cancel. It is a deliberate trade: it lets the network learn a
  residual rather than the whole image, converging far faster — which matters
  given a single-shot training budget.

No GAN: the brief explicitly asks for restoration "without hallucinating or
destroying real structure".

## Loss

```
L = Charbonnier + 0.15 * (1 - SSIM)      [+ 0.05 * LPIPS for the final 10% of steps]
```

- Charbonnier over L2: better PSNR/SSIM trade-off and robust to the heavy-tailed
  speckle outliers.
- **Single-scale SSIM, not MS-SSIM.** MS-SSIM's default 5 scales need images of
  at least ~161 px; the GT training crops are 128x128. MS-SSIM is used only for
  reporting on full images.
- LPIPS is a scored metric but running VGG every step costs ~30% throughput for
  little gain, so it is enabled only for the final fine-tune. Inputs are
  3-channel-replicated and rescaled to **[-1,1]** as LPIPS expects.

## Training setup

| | |
|---|---|
| Data | 2880 train / 320 validation pairs, split frozen in `configs/base.yaml` |
| Crops | 64x64 LR -> 128x128 GT, random flips and 90-degree rotations |
| Optimiser | AdamW, betas (0.9, 0.9), weight decay 1e-4 |
| LR schedule | 1e-3, 2000-step warmup, cosine to 1e-6 |
| Batch size | 32, AMP, channels_last, grad-norm clip 1.0 |
| Checkpointing | Validate and checkpoint every 5000 steps, keep best by PSNR |

**Validation split.** KLA's slides show sample 000000 -> source `0001.png` and
sample 000500 -> source `0186.png`, i.e. samples are ordered by source image
with roughly 2-3 samples per source. A random per-index split therefore leaks
near-duplicate content into training, while a contiguous tail slice hands
validation a handful of sources seen nowhere else. We hold out **10 evenly
spaced contiguous blocks of 32** (indices 0-31, 320-351, ... 2880-2911):
contiguous keeps same-source samples together, spacing covers the full content
diversity.

**Schedule calibration.** `train.py` measures its own throughput over the first
200 steps and sizes the cosine schedule to fit the configured time budget, so
the learning rate reaches its minimum exactly when the budget expires. A cosine
schedule that does not finish leaves the model at a high LR and costs ~1 dB.

**Pre-flight gate.** Before any long run:

```bash
python train.py --overfit 2 --steps 400
```

This must exceed 40 dB on two pairs. If it does not, the pipeline is broken and
the long run would be wasted. It exits non-zero on failure so it can gate a script.

## Reproducibility

- Every hyperparameter lives in `configs/base.yaml`; nothing is hard-coded.
- Seeds fixed (`seed: 1337`) for Python, NumPy and Torch.
- Each validation appends a row to `results/run_log.csv` with the run id, git
  hash, seed, step, LR, loss, all three metrics, parameter count, and the full
  config as JSON.
- The checkpoint embeds its own model config, so `inference.py` rebuilds the
  architecture without reading any config file.

## Results

See `results/metrics.csv` and `results/qualitative.png`.

Baselines measured on the validation split:

| Method | PSNR |
|---|---|
| Naive bicubic upsample of NoisyLR (do-nothing baseline) | 23.18 dB |
| Perfect denoise + bicubic upsample (denoise-only ceiling) | 32.25 dB |
| **This model** | see `results/metrics.csv` |

The second row is the ceiling for anything that denoises perfectly but only
*interpolates* the missing resolution; a model that genuinely learns
super-resolution should exceed it.

Metric conventions, stated because implementations differ:

- **PSNR** — `data_range=1.0`, computed on the clipped prediction, averaged per image.
- **SSIM** — 11x11 Gaussian window, sigma=1.5, `data_range=1.0`. Equivalent to
  skimage's `gaussian_weights=True, sigma=1.5, use_sample_covariance=False`.
  skimage's *default* is a 7x7 uniform window and gives a different number.
- **LPIPS** — LPIPS-VGG on 3-channel-replicated grayscale, inputs in [-1,1].

## Inference performance

End-to-end runtime is a scored axis and covers script startup, model init, disk
reads, inference and disk writes. `inference.py` accordingly:

- imports only `torch`, `numpy` and `argparse` at module level — no yaml, lpips,
  skimage or matplotlib, each of which would add import time for no benefit;
- reads and writes on a thread pool (npy I/O releases the GIL);
- groups inputs by resolution and runs them in batches under `inference_mode`,
  with `channels_last`, pinned memory, non-blocking transfers and fp16 autocast;
- skips `torch.compile` by default (30-60 s of compile time will not amortise
  over a small test set) — available behind `--compile`.

Optional `--tta` enables x8 self-ensembling: roughly +0.2 dB for ~8x the
runtime. Off by default, since throughput is scored.

## External resources

No external datasets or pretrained weights are used for the restoration model
itself; it is trained from scratch on the official KLA data plus synthetic pairs
derived from that same data.

`lpips` (BSD-2-Clause) supplies the VGG-based perceptual loss used in the final
fine-tune and for reporting. Its VGG16 backbone carries ImageNet-pretrained
weights distributed with the package. It is an optional dependency: training
degrades gracefully to Charbonnier + SSIM if it is unavailable, and
`inference.py` never imports it.

## Known limitations

- Trained on the 256->128 pairs that were released; the 512->256 case is handled
  by the fully-convolutional design and verified for shape correctness, but has
  no paired data to validate accuracy against.
- Heavy speckle (low L) over fine high-frequency texture is the dominant failure
  mode — the model smooths texture it cannot distinguish from noise. Examples in
  `results/qualitative.png`.
- The degradation engine assumes the three named mechanisms only, per the brief.
